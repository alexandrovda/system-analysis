# Архитектура микросервисов MCF

## Выбор внутреннего архитектурного стиля

Для каждого микросервиса выбран внутренний архитектурный стиль на основе его ключевых характеристик и внешних ограничений.

---

## Итоговая таблица

| # | Микросервис | Внутренний стиль | Ключевые характеристики |
|---|-------------|-----------------|------------------------|
| 1 | **Testing Service** | Microkernel | Scalability высокая, Agility высокая, Deployability высокая (недельный релиз) |
| 2 | **Matching Service** | Microkernel | Maintainability высокая, Modifiability высокая, Configurability высокая |
| 3 | **Billing Service** | Microkernel | Consistency высокая, Securability высокая, Configurability высокая (новые способы оплаты) |
| 4 | **Payroll Service** | Pipeline | Consistency высокая, Workflow (начисление → инвойс → Золотая шляпа) |
| 5 | **OrderProcessing Service** | Pipeline | Workflow (создание → матчинг → выполнение → оплата) |
| 6 | **IncentiveService** | Layered | Simplicity высокая, Securability высокая (секретность) |
| 7 | **ClientAcquisition Service** | Layered | Simplicity высокая, Securability высокая, Usability средняя |

---

## Детальные обоснования

### 1. Testing Service — Microkernel

**Ключевые характеристики:**
- Scalability высокая (DDoS)
- Agility высокая (быстрая проверка гипотез)
- Deployability высокая (недельный релиз)

**Почему Microkernel:**
- ⭐⭐⭐ Agility — быстрая замена алгоритмов тестирования
- ⭐⭐⭐ Deployability — отдельные плагины деплоятся независимо
- ⭐⭐⭐⭐ Configurability — менеджеры конфигурируют тесты (US-110)
- ⭐⭐⭐⭐ Simplicity — ядро простое, сложность в плагинах

**Как работает:**
- Ядро: приём заявок, управление кандидатами
- Плагины: разные наборы тестов, алгоритмы оценки
- Менеджеры добавляют/меняют плагины без изменения ядра

---

### 2. Matching Service — Microkernel

**Ключевые характеристики:**
- Maintainability высокая (автономия разработчиков)
- Modifiability высокая (добавлять/редактировать шаги)
- Configurability высокая (US-300)

**Почему Microkernel:**
- ⭐⭐⭐⭐ Maintainability — каждый шаг алгоритма изолирован
- ⭐⭐⭐⭐ Modifiability — добавление шагов без изменения ядра
- ⭐⭐⭐ Configurability — последовательность шагов настраивается
- ⭐⭐⭐⭐⭐ Domain Partitioning — каждый шаг — отдельный домен

**Как работает:**
- Ядро: orchestration шагов, расчёт финального рейтинга
- Плагины: шаги алгоритма (map, reduce, расчёт рейтингов)
- Разработчики матчинга добавляют/меняют плагины автономно

---

### 3. Billing Service — Microkernel

**Ключевые характеристики:**
- Consistency высокая (нельзя терять платежи)
- Securability высокая (CatFinComplience)
- Configurability высокая (новые способы оплаты)

**Почему Microkernel:**
- ⭐⭐⭐⭐ Configurability — новые способы оплаты как плагины
- ⭐⭐⭐⭐ Maintainability — изоляция платёжных провайдеров
- ⭐⭐⭐ Domain Partitioning — каждый провайдер — отдельный плагин
- ⭐⭐⭐⭐ Evolvability — замена провайдера без изменения ядра

**Как работает:**
- Ядро: генерация инвойсов, расчёт скидок, учёт платежей
- Плагины: интеграции с платёжными системами ( Visa, MasterCard, etc.)
- Финотдел добавляет новые способы оплаты как плагины

---

### 4. Payroll Service — Pipeline

**Ключевые характеристики:**
- Consistency высокая (точные финансовые правила)
- Workflow: начисление → инвойс → выплата через "Золотую шляпу"

**Почему Pipeline:**
- ⭐⭐⭐⭐⭐ Workflow — классический конвейер выплат
- ⭐⭐⭐⭐ Testability — каждый шаг тестируется отдельно
- ⭐⭐⭐ Evolvability — можно добавлять шаги (например, налоги)
- ⭐⭐⭐ Interoperability — интеграция с "Золотой шляпой"

**Как работает:**
- Шаг 1: Расчёт выплат (60% от стоимости, штрафы)
- Шаг 2: Генерация инвойса
- Шаг 3: Отправка в "Золотую шляпу"
- Шаг 4: Подтверждение выплаты
- Шаг 5: Уведомление воркера

---

### 5. OrderProcessing Service — Pipeline

**Ключевые характеристики:**
- Workflow: создание → матчинг → выполнение → оплата
- Usability высокая (все пользовательские интерфейсы)

**Почему Pipeline:**
- ⭐⭐⭐⭐⭐ Workflow — оркестрация заказов как конвейер
- ⭐⭐⭐ Interation — взаимодействие с пользователем на каждом шаге
- ⭐⭐⭐ Interoperability — интеграции с другими сервисами
- ⭐⭐ Evolvability — можно добавлять шаги (например, проверку качества)

**Как работает:**
- Шаг 1: Создание заказа (клиент)
- Шаг 2: Матчинг (запрос в Matching Service)
- Шаг 3: Сборка расходников (уведомление SuppliesAssembly)
- Шаг 4: Выполнение (воркер)
- Шаг 5: Проверка качества (менеджер)
- Шаг 6: Оплата (запрос в Billing Service)

---

### 6. IncentiveService — Layered

**Ключевые характеристики:**
- Simplicity высокая (15 менеджеров)
- Securability высокая (секретность ставок)
- Deployability высокая

**Почему Layered:**
- ⭐⭐⭐⭐⭐ Simplicity — максимальная простота
- ⭐⭐⭐⭐⭐ Cost — минимальная стоимость разработки
- ⭐⭐ Security — изоляция через слой авторизации
- ⭐⭐⭐⭐⭐ Testability — простое модульное тестирование

**Как работает:**
- Presentation Layer: UI для менеджеров (ставки, результаты)
- Business Layer: расчёт выигрышей/проигрышей
- Data Layer: хранение ставок, результатов заказов
- Security Layer: авторизация (только менеджеры)

---

### 7. ClientAcquisition Service — Layered

**Ключевые характеристики:**
- Simplicity высокая (Generic поддомен)
- Securability высокая (персональные данные клиентов)
- Usability средняя (автоматическое попадание клиентов)

**Почему Layered:**
- ⭐⭐⭐⭐⭐ Simplicity — максимальная простота для Generic поддомена
- ⭐⭐⭐⭐⭐ Cost — минимальная стоимость разработки
- ⭐⭐ Security — изоляция персональных данных клиентов
- ⭐⭐⭐⭐⭐ Testability — простое модульное тестирование

**Как работает:**
- Presentation Layer: API для получения аккаунтов из НСВ
- Business Layer: обработка и валидация данных клиентов
- Data Layer: хранение аккаунтов клиентов
- Integration Layer: интеграция с внешней системой НСВ
